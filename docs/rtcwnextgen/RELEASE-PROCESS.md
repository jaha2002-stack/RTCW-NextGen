# RTCW NextGen — инженерные артефакты

Инженерный ZIP содержит Windows x64/DX12 сборку RBDoom3BFG, `rbdmap.exe`, утилиту `tools/compile-native-level.py` и проверку рендерера. Для запуска Release на чистой Windows требуется Microsoft Visual C++ Redistributable x64. Утилита сборки карты требует Python 3.9 или новее.

1. Распакуйте ZIP и откройте `Run Renderer Smoke.cmd`. Должно появиться окно с красной левой и синей правой половиной.
2. Измените размер окна. Оба цвета должны заполнить окно в новом размере.
3. Нажмите Escape. Программа должна завершиться и сохранить PNG. Снимок и журнал находятся в отдельной папке этого запуска внутри `%LOCALAPPDATA%\RTCW-NextGen`.

Для компиляции авторской MAP из папки распакованного ZIP запустите `python tools/compile-native-level.py <source.map> --rbdmap rbdmap.exe --assets <author-assets> --out <new-level-directory>`. В каталоге ресурсов могут находиться `materials/`, `textures/` и `def/`. Параметр `--aas aas48` включает проверку навигационного результата при наличии соответствующего определения. Компилятор сохраняет геометрию `.proc`, коллизии `.cm` и контрольные суммы в новом каталоге.

- GitHub Actions формирует ZIP из Release-бинарников, DXIL, исходной конфигурации и лицензионных документов. Используется явный список входов. ZIP проверяется распаковкой, сверкой содержимого и SHA-256.
- `BUILD-MANIFEST.json` фиксирует исходный коммит. Соответствующий исходный код доступен в [jaha2002-stack/RTCW-NextGen](https://github.com/jaha2002-stack/RTCW-NextGen) по этому SHA. Ревизии, необходимые для checkout подмодулей, указаны в том же манифесте.
- Для кандидата игрового этапа требуются проверки A–D и доступные проверки E, лицензионный аудит упаковки и карточка конкретного игрового сценария по Handoff. Кандидат публикуется как prerelease после проверки этой ревизии.
- Для продвижения нужны явная запись приёмки, исходный коммит и подтверждённый SHA-256. Публикуется тот же принятый ZIP. Изменения бинарников, шейдеров или настроек требуют повторной проверки в игре.
