# Ограничения Native Playable Level Prototype

| Класс | Операция | Независимая работа и условия проверки |
| --- | --- | --- |
| `POLICY_BLOCKER` | Воссоздание `escape1`, включая точную оригинальную геометрию, планировку и узнаваемые архитектурные элементы. Переход на нативные AI, физику и сценарии сохраняет это требование к уровню. | Доступны универсальные инструменты для авторских уровней, структурная диагностика и проверка нативных систем на авторских входах. Для самостоятельного игрового кандидата подходит собственная планировка. |
| `TECHNICAL_BLOCKER` | Передать скомпилированный `IBSP` непосредственно в `dmap`, `convertMapQuakeToDoom` или `idRenderWorld::InitFromMap`. Наблюдаемые входы этих путей — текстовая `.map` либо нативный `.proc/.bproc` для загрузчика мира. | Проверена компиляция авторской `.map` в нативные данные. Совместимые материалы и навигация требуют отдельных настроек. |
| `ENVIRONMENT_BLOCKER` | Проверить аппаратный DirectX 12 в облачной Linux-сессии. | Выполняются Windows CI для компиляции и упаковки, программный Vulkan для кадра и отмены. Для аппаратной приёмки нужен Windows-хост и допустимый игровой кандидат. |

Для авторского конвейера доступны исходники, компилятор и разрешённые ресурсы проверки. Лицензии RBDoom3BFG и закреплённых RTCW-SP/ioRTCW ранее рассмотрены. Новый инструмент использует исходный компилятор проекта и собственные авторские входы. [Лицензии и ревизии](adr/0001-upstream-baseline.md) · [Аудит переиспользования](NATIVE_LEVEL_REUSE_AUDIT.md)
