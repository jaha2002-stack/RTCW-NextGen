# План Native Playable Level Prototype

Подсистемы Stage II используют RBDoom3BFG и авторские данные для независимых инженерных проверок. История режима совместимости сохранена на предыдущей ветви. [Текущая архитектура](architecture.md) · [Ограничения](STAGE_II_BLOCKER_ANALYSIS.md)

| Фаза | Текущее состояние | Следующая проверка |
| --- | --- | --- |
| P01 · Native Engine Bootstrap | Нативный предпросмотр запускается с собственными материалами и шейдерами. Windows CI собирает движок и инструменты. | Выделить запуск полноценного нативного игрового режима для авторской карты. |
| P02 · Level Pipeline | Исходный текстовый MAP собирается в `.proc`, `.cm` и опциональный `.aas48`. Проверены масштаб Valve 220 и точные трассы пола и стен. | Добавить авторский проход между двумя областями и проверить изменение видимости. |
| P03 · Materials & Asset Mapping | Два материала авторского уровня видны из контрольной камеры. | Зафиксировать сопоставление объявлений материалов и проверку прозрачной поверхности на авторском входе. |
| P04 · Native Player & Physics | Генерация коллизий и точечные трассы подтверждены. | Создать нативного игрока и проверить движение, ступень и камеру. |
| P05 · Native Gameplay & AI | Подтверждена генерация навигации для комнаты. | Проверить маршрутизацию между областями с авторской дверью, затем базовые события сущностей. |
| P06 · Baseline | Компиляция и пакет инструментов проверяются в CI. | Игровому кандидату нужны запускаемый нативный сценарий и подтверждение всех критериев приёмки. |

Графические технологии Stage III требуют отдельного согласования после приёмки. [Матрица приёмки](STAGE_II_ACCEPTANCE_REPORT.md)
