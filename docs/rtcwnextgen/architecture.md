# Архитектурный аудит Stage II

Сопоставлены RBDoom3BFG `ea29c006e84f`, ioRTCW SP `438e7d413b5f` и лицензия официального RTCW-SP `70951bc71b73`. Владелец утвердил **Variant A** с RBDoom3BFG как основным движком и слоем совместимости поверх его интерфейсов. Результаты ниже фиксируют наблюдаемые интерфейсы и зависимости. ## Проверки передачи данных в Variant A

1. **Нативная передача геометрии RBDoom3BFG.** Проверяемый следующий эксперимент на авторской карте — поверхности и трансформации в `idRenderWorld`, затем видимость и динамический объект. Текущий [проверочный набор](TESTING.md) подтверждает сборку, компиляцию авторской карты и вывод синтетического кадра. Передача BSP-геометрии в этот API остаётся `NOT_IMPLEMENTED`.
2. **Офлайн-представление для RBDoom3BFG.** `rbdmap` подтверждён на исходном id Tech 4 `.map` с собственными тестовыми материалами. Преобразователь IBSP в `.proc` отсутствует. Для сравнения требуются одинаковые исходные авторские поверхности, координаты, границы мира и видимость в обеих ветках эксперимента.

Держать независимый инструмент чтения форматов вне `idGameLocal`. Для будущих изолированных проверок формат входа остаётся little-endian, сериализуемые данные имеют явную разрядность. Указатели и временная память принадлежат вызывающему модулю до завершения вызова. Render handles принадлежат рендереру, а обновления мира проходят в его потоке. Офлайн-представление можно использовать внутри Variant A для сравнения форматов и проверки входов. Сравнительного измерения пока нет.
